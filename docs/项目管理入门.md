# 项目管理入门（小白版）

项目管理的本质就三句话：**小步走、每步能验收、随时留快照（git）**。不需要任何 fancy 工具。

## 你现在有什么

- 一个文件夹 `~/booktalk`，里面是 M2 的代码（能跑、能测）。
- 一个路线图（`README.md` 里的 M0–M5 清单）。

## 核心概念：里程碑（Milestone）

把大目标切成一个个能「验收」的小步。每个里程碑只回答一个问题：

| 里程碑 | 要回答的问题 | 状态 |
|---|---|---|
| M2 | 能不能把书导进去、文字提问、答对并给出引用出处？ | ✅ 代码已写好 |
| M1 | 能不能对着麦克风说话、它实时用声音回、能被你打断？ | ⬜ 下一步 |
| M3 | 能不能一边语音问答、一边在屏幕上显示引用？ | ⬜ |
| M4 | 能不能在手机上、离开家也能用？ | ⬜ |
| M5 | （可选）要不要双人播客？ | ⬜ |

**每完成一步，就在 README 的复选框上打勾。没打勾 = 没完成。** 永远只盯着「当前这一步」做，别想着把 M1–M5 一次做完。

## Git 三步（每次开工 / 每做完一件小事）

```bash
cd ~/booktalk
git status                        # 1) 看：改了哪些文件
git add -A                        # 2) 暂存：把改动装进购物车
git commit -m "做了什么"          # 3) 提交：存一个快照
```

三条铁律：

1. **提交要小**：一次只做一件事（「加 PDF 导入」「修引用 bug」），别攒一大坨才提交。
2. **信息写清楚**：`feat: 加了 PDF 导入` / `fix: 修引用编号错位`。
3. **别在 main 上乱改**：想试新东西，先 `git checkout -b 新分支`，好了再合回来。

## 开工前的 3 个检查（防止白做）

1. `git status` 确认当前是干净的（或知道自己改了什么）。
2. 想清楚「这一步做完，怎么才算成功」——用一句话写下来。
3. 做完 → 跑通 → 提交。再开始下一步。

## 常用命令速查

| 想做什么 | 命令 |
|---|---|
| 看改了啥 | `git status` |
| 看历史 | `git log --oneline` |
| 存快照 | `git add -A && git commit -m "..."` |
| 撤销未提交的改动 | `git checkout -- <文件>` |
| 开新分支 | `git checkout -b 分支名` |
| 回到过去某个版本看 | `git log` 找到编号，`git checkout <编号> -- <文件>` |

## 运行 / 测试（现在就能做）

见 `README.md` 的「快速开始」。简版：

```bash
cd ~/booktalk
source .venv/bin/activate          # Windows 用 .venv\Scripts\activate
python -m booktalk.ingest "data/books/你的书.pdf"
python -m booktalk.chat
```
